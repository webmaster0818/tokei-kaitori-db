## 1. (a) 16ページを非公開にした場合のガードの動き（実測）

10/9 スナップショットからウォッチニアン 9/30 取得の引き継ぎ行（58件・43型番）を除いた `2026-10-15.json` を作り、作業ツリーで `npm run build` → `daily-update.sh` のガード部分を同じ式で実行:

```

消えたURL = expiry-2026-10-15.md の16本と完全一致
PREV=233 NOW=217 threshold=221 （= 233*95/100 の整数切り捨て）
GUARD: STOP（notify-drop で Discord 通知 → exit 1。commit・push・デプロイなし）
```

- 1日に許される減少は **12URL まで**（233 → 221）。16 減るので確実に止まる。
- 🚨 **止まった後は自然には戻らない**: ガードは `git show HEAD:public/sitemap.xml` と比べるが、止まった日は commit しないので HEAD は 233 のまま。**翌日も 233 vs 217 で比べて止まり、毎日 Discord 通知が出る**。誰かが一度 commit+push するまで価格更新も止まる。

## 3. (c) ガードを1回だけ通す方法

### c-1 コード変更なし（10/15 当日に手でやる）
ガードで止まった後、作業ツリーには 10/15 のスナップショットと 217 の sitemap・`out/` が残っている。中身を確認してから
`git add -A && git commit -m "daily: 2026-10-15（承認済みの減少 233→217）" && git push origin HEAD:main`（＋スクリプトと同じ wrangler デプロイ）。
これで HEAD が 217 になり、翌日からガードは 217 基準に戻る。**11:25 の実行が終わってから人が行う必要がある。**

### c-2 最小の変更案（wip ブランチ `wip/expiry-sim-2026-10-10` コミット `d69bbea5`・本番未適用）
`scripts/daily-update.sh` のガード 1 か所だけ（+8/−1 行）。リポの外に許可ファイル `~/.tokei-allow-drop` を「日付 最低URL数」の1行で置くと、**その日・その数以上のときだけ 1 回通し、使ったらファイルを消す**:

```bash
ALLOW="${TOKEI_ALLOW_FILE:-$HOME/.tokei-allow-drop}"
if [ "$PREV" -gt 0 ] && [ "$NOW" -lt $(( PREV * 95 / 100 )) ] && [ -f "$ALLOW" ] \
   && read -r A_DATE A_MIN < "$ALLOW" && [ "$A_DATE" = "$(date +%F)" ] && [ "$NOW" -ge "${A_MIN:-999999}" ]; then
  say "⚠️ 公開URLが ${PREV} → ${NOW}。許可ファイル（${A_DATE} 最低${A_MIN}）により今回だけ通します"
  rm -f "$ALLOW"
elif [ "$PREV" -gt 0 ] && [ "$NOW" -lt $(( PREV * 95 / 100 )) ]; then
  （従来どおり停止）
```
使い方: 承認後に `echo "2026-10-15 215" > ~/.tokei-allow-drop`。

ガード部分だけを取り出したテスト（取得・commit・push・デプロイは実行せず、通知はスタブ。PREV=233 / NOW=220）:

```
許可ファイルなし                     → 停止
日付が違う（2026-10-15 を 10/10 に）  → 停止（ファイルは残る）
今日・最低225（NOW=220 が下回る）     → 停止
今日・最低215                        → 通過・ファイル削除
もう一度（消費済み）                  → 停止
```
- 「最低URL数」を付けたのは、承認した減少（−16）より大きく落ちた日（別の障害が重なった日）まで通さないため。
- ガードを恒久的に緩める変更ではない。
